# Модуль "Типы занятий" (Lesson Types)

Этот модуль реализует полную двустороннюю синхронизацию таблицы `lesson_types` между локальной базой SQLite и Supabase.

## Структура модуля

```
lib/features/lesson_types/
├── data/
│   ├── lesson_type_model.dart              # Модель данных
│   ├── lesson_types_repository.dart        # Локальный репозиторий (SQLite)
│   ├── lesson_types_remote_repository.dart # Удаленный репозиторий (Supabase)
│   └── lesson_type_repository.dart         # Основной репозиторий с синхронизацией
└── presentation/
    └── (UI компоненты будут добавлены при необходимости)
```

## Возможности

### ✅ Локальная работа
- Создание, чтение, обновление и удаление типов занятий в SQLite
- Поиск по названию и описанию
- Мягкое удаление (записи помечаются как удаленные)

### ✅ Синхронизация с Supabase
- Двусторонняя синхронизация данных
- Автоматическая отправка локальных изменений в Supabase
- Получение изменений из Supabase
- Обработка офлайн-режима

### ✅ Пользовательский интерфейс
- Тестовый экран для проверки функциональности
- CRUD операции
- Индикатор статуса синхронизации

## Настройка

### 1. Создание таблицы в Supabase

Выполните SQL-скрипт `scripts/create_lesson_types_table.sql` в SQL Editor Supabase:

```sql
CREATE TABLE IF NOT EXISTS lesson_types (
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 2. Настройка RLS (Row Level Security)

В Supabase Dashboard включите RLS для таблицы `lesson_types` и создайте политики доступа.

### 3. Обновление базы данных

Таблица `lesson_types` автоматически создается в SQLite при обновлении версии базы данных до 7.

## Синхронизация

### Автоматическая синхронизация
- При запуске приложения выполняется полная синхронизация
- При добавлении/изменении/удалении данных происходит асинхронная синхронизация

### Ручная синхронизация
- Нажмите кнопку "Синхронизация" в тестовом экране
- Или вызовите `repository.syncLessonTypes()`

### Обработка офлайн-режима
- Все операции сначала сохраняются локально
- При отсутствии сети данные помечаются как `pending`
- При восстановлении соединения выполняется синхронизация

## Статусы синхронизации

- `synced` - запись синхронизирована
- `pending` - ожидает синхронизации
- `error` - ошибка синхронизации

## Логирование

Все операции синхронизации логируются через `print` для отладки.

## Безопасность

- Все операции с Supabase выполняются через анонимный ключ
- RLS политики контролируют доступ к данным
- Локальные данные защищены SQLite

## Производительность

- Индексы в Supabase для быстрого поиска
- Пакетная обработка синхронизации
- Асинхронные операции не блокируют UI
